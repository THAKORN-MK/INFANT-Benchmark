# วิธีที่ใช้ในบทความ Sinc-Mamba-KAN และสถานะการทำตาม

อ้างอิงบทความ DOI `10.1109/ACCESS.2026.3733522` เลขหน้าด้านล่างนับตามหน้า PDF เริ่มจากหน้าแรก บทความจำแนก **เสียงตาม label DBL ที่ผู้ประเมินกำหนด** ไม่ได้ยืนยันสาเหตุทางสรีรวิทยาของทารกโดยตรง (หน้า 3)

## 1. วิธีหลัก Sinc-Mamba-KAN

เสียงแต่ละคลิปถูกแปลงเป็น mono 16,000 Hz ตัดหรือเติมศูนย์เป็น 2 วินาที (32,000 samples) และทำ peak normalization ก่อนส่งเข้าการวิเคราะห์สองแขนง (หน้า 5)

1. **แขนงสัญญาณเสียง:** เริ่มจาก SincConv 64 filters ขนาด kernel 251, stride 8 และ Hamming window แล้วใช้ convolution, batch normalization, LeakyReLU และ pooling สกัดรูปแบบในเสียง ก่อนส่งลำดับเข้า Mamba ซึ่งตั้ง `d_model=128`, `d_state=16`, expansion 2 และเฉลี่ยตามเวลาเพื่อได้เวกเตอร์ 128 ค่า
2. **แขนงคุณลักษณะเสียง:** สกัดคุณลักษณะ 213 ค่า ใช้ข้อมูลฝึก fit ตัวปรับมาตรฐานและ mutual-information selector เพื่อเลือก 100 ค่า ก่อนส่งผ่านชั้น projection เป็นเวกเตอร์ 64 ค่า
3. **รวมผล:** ต่อเวกเตอร์ 128 และ 64 เข้าด้วยกันเป็น 192 ค่า แล้วให้ KAN จำแนกเป็น 5 คลาส ได้แก่ eairh, eh, heh, neh และ owh (หน้า 3 และ 5)

บทความระบุรายละเอียดบางส่วนไม่ครบพอจะพิสูจน์ว่าทำซ้ำได้ตรง เช่น ลำดับคุณลักษณะทั้งหมด, ขนาด noise, seed จริง และรายละเอียด PolyLoss บางส่วน การเขียนโค้ดในโครงการนี้จึงเป็นการพัฒนาตามบทความ ไม่ใช่โค้ดผู้เขียน

## 2. วิธีจัดการข้อมูลและเพิ่มข้อมูล

- สกัดคุณลักษณะความถี่โดยใช้ FFT 512 และ hop 160 samples (10 ms ที่ 16 kHz)
- ระหว่างฝึกมี Gaussian noise และ circular time shift บน waveform รวมทั้ง noise บน feature; บทความไม่ได้ให้ขนาด/โอกาสทุกค่าอย่างครบถ้วน
- ใช้ class-weighted cross-entropy เพื่อลดผลของจำนวนคลาสไม่สมดุล ร่วมกับ PolyLoss-2, label smoothing 0.05, AdamW, learning rate 0.001, weight decay 0.0001, cosine schedule และ gradient clipping 2.0 (หน้า 5–7)
- full-capacity ใช้ 80 epochs ส่วนการทดลองบางรายการใช้ reduced-compute 45 epochs; ห้ามนำสองการตั้งค่ามาเรียกรวมว่าเหมือนกัน (หน้า 7)

## 3. วิธีประเมิน

1. **Clip-level stratified 5-fold:** แบ่งข้อมูลตามสัดส่วนคลาสเป็น 5 ส่วน ผลัดกันใช้แต่ละส่วนเป็นชุดประเมิน 1 ครั้ง
2. **Infant-disjoint stratified group 5-fold:** สำหรับ Dataset 2 บทความจัดกลุ่มด้วย identifier ที่ตีความว่าเป็น infant ID แล้วพยายามไม่ให้ ID เดียวกันอยู่ทั้งฝึกและประเมิน (หน้า 6–8) ในโครงการนี้ยังต้องตรวจว่า metadata ยืนยันความหมายของ ID ได้จริงหรือไม่
3. **Cross-dataset:** ฝึกบน Dataset หนึ่งและประเมินบนอีก Dataset โดยตัดคลิปที่ซ้ำข้ามชุดออกตามที่บทความอธิบาย (หน้า 13) ไม่ใช่การประเมินที่ทำได้โดยนำทุกไฟล์สองชุดมาเทรวมกัน
4. รายงาน accuracy, balanced accuracy, macro-F1, one-vs-rest ROC AUC และ confusion matrix ส่วนผลที่อยู่ในบทความเป็นผลของผู้เขียน ไม่ใช่ผลของโครงการนี้ (หน้า 6–9)

การทำตามครั้งนี้ควรตั้งวิธีเลือก checkpoint โดยไม่ใช้ outer evaluation fold ซึ่งเป็นรายละเอียดที่ต้องเปิดเผยว่าเป็นแนวทางของเรา หากแตกต่างจากบทความ

## 4. โมเดลอื่นที่บทความเปรียบเทียบ

บทความกล่าวถึง **เก้าโมเดลรวมโมเดลที่เสนอ** ในการเปรียบเทียบบน Dataset 1 (หน้า 7–8):

1. Multiple-instance learning (MIL) พร้อม gated attention
2. Source–filter cepstral network (NSF)
3. Hand-crafted features + mutual-information selection + SVM
4. 2-D CNN ที่ใช้ MFCC
5. Conformer
6. Source–filter split SincNet
7. SincNet ร่วมกับ hand-crafted features
8. SincNet
9. Sinc-Mamba-KAN ซึ่งเป็นโมเดลหลักของบทความ

โมเดลเปรียบเทียบเหล่านี้ **ยังไม่ได้สร้างหรือฝึกในโครงการนี้** และชื่อที่คล้ายกันไม่ได้ยืนยันว่าใช้ implementation เดียวกับบทความ

## 5. การวิเคราะห์ส่วนประกอบและการอธิบายผล

- **Ablation:** ทดลองตัดบางส่วนของโมเดล เช่น Mamba, KAN หรือแขนง hand-crafted features เพื่อดูผลของส่วนประกอบ โดยบทความใช้ reduced-compute สำหรับ ablation (หน้า 8–9)
- **Learned sinc filters:** ตรวจขอบเขตความถี่ของ filters ที่โมเดลเรียนรู้
- **Integrated Gradients และ branch occlusion:** ดูผลต่อการตัดสินใจของโมเดลหลักโดยตรง
- **SHAP และ LIME:** อธิบายผ่าน Random Forest surrogate ไม่ใช่การคำนวณกับโมเดลหลักโดยตรง บทความตรวจ fidelity ของ surrogate ด้วย (หน้า 9–12)

วิธีอธิบายผลเหล่านี้ยังไม่ได้ implement หรือประเมินในโครงการนี้ และความสอดคล้องของคำอธิบายไม่ได้พิสูจน์ความถูกต้องทางการแพทย์

## 6. สิ่งที่โครงการเริ่มสร้างแล้ว

- `manifest.py`: ตรวจ metadata และ SHA-256 โดยอ่านอย่างเดียว รองรับการสะกดชื่อโฟลเดอร์ Tier 2 ที่ต่างกัน โดยไม่แก้ metadata/เสียง
- `audio.py`: ค่า 16 kHz, mono, 2 วินาที และ peak normalization ตามบทความ ส่วนการตัดจากต้นคลิป เติมศูนย์ท้ายคลิป และการ resample ด้วย SciPy เป็น **สมมติฐานของเรา**
- `features.py`: ตัวแทน 213 ค่า ประกอบด้วย 40 MFCC และ 40 delta อย่างละ mean/std, 12 chroma mean/std, 6 contrast mean/std, 6 spectral statistics mean/std และ 5 ค่าจาก pitch/voicing โดยเลือก `pyin`, ช่วง 65–1000 Hz, frame 2048, 128 mel bins และพารามิเตอร์ที่ไม่ได้ระบุอื่นเป็น **สมมติฐานของเรา** จำนวน 213 เท่ากันไม่ได้ยืนยันว่าสูตร ชื่อ ลำดับ และผลเหมือนของผู้เขียน
- ผู้ใช้รัน `model.py`, `training.py` และ `train.py` ครบ 5 folds แล้ว ดู [รายงานผลครั้งที่ 1](../reports/run_20261116T193124Z_05d86d55d2/REPORT.md) ทั้งนี้ยังไม่ได้พิสูจน์ว่า implementation เท่ากับบทความทุกขั้นตอน

## 7. ผลสำรวจข้อมูลที่ผู้ใช้เพิ่งนำมาใส่

README ระบุ Version 1.0; metadata มี 1,551 แถวแบ่งเป็น 337 และ 1,214 แถว และเมื่อตีความชื่อโฟลเดอร์ Tier 2 ที่สะกดต่างกันแล้วพบไฟล์ครบทุกแถว การตรงกันนี้ยังไม่ใช่การตรวจ checksum เทียบ release ภายนอก

พบ SHA-256 ซ้ำ 198 กลุ่ม โดย 180 กลุ่มข้าม tier และ 3 กลุ่มมี label ขัดแย้งข้าม tier; ภายใน Tier 2 พบ hash ซ้ำ 19 กลุ่มแต่ไม่พบ hash ซ้ำข้าม label และมีชื่อ suffix ไม่ตรง parent folder 1 ไฟล์ ต้องพิจารณา group/label policy จากหลักฐานก่อนเทรนหรือประเมิน ข้อมูล SHA-256 นี้ตรวจไฟล์ที่ bytes ตรงกันเท่านั้น ไม่พิสูจน์ว่าเสียงที่เข้ารหัสหรือตัดต่างกันไม่ซ้ำกัน
